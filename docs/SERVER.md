# 简幻欢服务器测试

这份脚本用于你提供的简幻欢开服环境。由你在面板上传并运行，开发者未连接、登录或操作 `play.simpfun.cn:25342`。

## 上传

1. 先在面板停止现有游戏进程，并把原来的 `start.sh` 另存为 `start-original.sh`。
2. 上传 `Tavern-Battlegrounds-0.2.0-compat.1-Server.zip`，在 `/home/container` 解压。完成后应有 `/home/container/tavern-mod/install.mjs`。
3. 将提供的新 `start.sh` 上传到 `/home/container/start.sh`。面板启动命令设为 `bash /home/container/start.sh`。
4. 首次启动会准备原版 0.2.6、复制旧服可复用素材、导入模组、安装依赖和检查资源。完成后继续通过你自己的 `play.simpfun.cn:25342` 进入。

首次准备需要服务器能访问原版 GitHub 仓库、npm 和上游素材源。模组本身从你上传的 ZIP 导入，不要求服务器访问私有 GitHub 仓库，也不需要填写 GitHub 令牌。

## 目录和端口

- 旧服 `/home/container/Stronghold-Protocol` 保留，不被重置、覆盖或删除。
- 新测试服 `/home/container/tavern-instances/0.2.0-compat.1` 单独运行。
- 默认监听 `0.0.0.0`，端口按 `PORT` → `SERVER_PORT` → `3000` 取值。外部地址的 25342 不一定等于容器内部端口，应沿用面板分配的内部端口。连接失败时先核对日志里的监听端口与面板映射。
- 原脚本使用 Misyra 分支；本测试脚本固定原版 sganggs 的 0.2.6 提交，不追踪分支最新版本。不包含旧服分支的额外管理、审核或网络功能，也不执行原脚本里的审核降级替换。
- 不使用 `pkill -9 node`，不清空 `.state`，不在每次开服时 `git reset --hard`。

## 独立开关

房主开局前可分别设置酒馆法术、英雄策略和多人房间。多人关闭为 4 席，开启可选 8 或 12 席；存在第 5 席以上玩家时不能强行缩回 4 席。鲍勃、聊天、伤害看板由每位玩家分别开关。

伤害看板在最终结算显示玩家统计，不是实时逐干员 DPS。聊天是短时气泡，不带历史聊天记录。多人卡池与机变规则沿用适配来源插件。

## 建议实际验收顺序

1. 两人连接，关闭多人扩容，确认原来的法术、英雄与鲍勃正常。
2. 开启 8 席，至少 5 位玩家进房；验证聊天收发、准备和策略轮选。然后再测 12 席。
3. 购买、刷新、英雄主动技能与法术同时操作，尤其关注给队友奖励、支援协防、智慧球刷新。
4. 完成一局查看伤害看板，分别关闭聊天／看板／鲍勃，确认其他功能仍正常。
5. 刷新重连、退出再进房，确认不串房聊天，不重播旧气泡。

保留面板日志。反馈请附版本、房间人数、策略／法术、操作步骤、客户端和截图。当前服务器只对中国境内开放，因此线上结果需要你实际验收；本地的自动化测试不能替代这一步。

## 检查与回退

- 只准备和校验、不启动：`bash /home/container/start.sh check`
- 卸载测试副本里的模组：停服后执行 `bash /home/container/start.sh uninstall`。再次用新脚本启动会重新导入。
- 恢复旧服：停服，把旧脚本恢复为 `start.sh`，或把面板启动命令改为 `bash /home/container/start-original.sh`。注意旧脚本仍带有原来的自动更新、强杀进程等行为。

本包不包含安卓 APK。Paper-Yuan 安卓分支将单独检测，当前不能把这份服务端 ZIP 当作安卓应用内可直接导入的模组包。
